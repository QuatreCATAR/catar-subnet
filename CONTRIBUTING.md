# 01 — Philosophie du projet
Le Subnet CATAR est conçu pour être :

ouvert,

améliorable,

transmissible,

documenté,

cohérent,

durable.

Chaque contribution vise à renforcer :

la stabilité du Passage CATAR,

la cohérence du Corpus,

la qualité du code,

l’autonomie du subnet,

la rétribution équitable des contributeurs,

la pérennité du projet même en l’absence de son créateur.

Le projet doit rester compréhensible, reproductible et maintenable par n’importe quel contributeur.

# 03 — Comment contribuer
Étape 1 — Forker le dépôt
Créez une copie personnelle du projet via GitHub.

Étape 2 — Créer une branche dédiée
Créez une branche pour votre contribution (ex. feature-miner, fix-doc, concept-update).

Étape 3 — Effectuer les modifications
Respectez la structure du projet, la modularité et la cohérence conceptuelle.

Étape 4 — Ajouter documentation et tests
Toute contribution doit inclure :

un README ou une note explicative,

un test minimal (même simple),

une justification conceptuelle si nécessaire.

Étape 5 — Soumettre une Pull Request
Décrivez clairement :

l’objectif,

l’impact,

la compatibilité,

les tests effectués.

# 04 — Règles de cohérence conceptuelle
Toute contribution doit respecter :

la logique du JEu,

la structure Absolu/Relatif,

la cohérence du Passage CATAR,

la neutralisation des dérives cognitives,

la stabilité conceptuelle du Corpus,

la distinction Moije / Soije,

les invariants conceptuels du Cycle CATAR.

Aucune modification ne doit altérer la structure conceptuelle du Corpus CATAR.

# 05 — Règles de modularité
Le Subnet CATAR est construit en modules indépendants.
Toute contribution doit :

être isolée dans un module,

ne pas casser les modules existants,

être testable indépendamment,

être documentée,

respecter la structure du dépôt.

# 06 — Règles de qualité
Les contributions techniques doivent inclure :

tests unitaires,

tests Ubuntu,

compatibilité subtensor,

absence de dépendances inutiles,

code clair et commenté.

Les contributions conceptuelles doivent inclure :

justification,

impact,

cohérence avec le Corpus,

compatibilité avec le Passage CATAR.

# 07 — Économie interne (50/50)
Le Subnet CATAR utilise un modèle économique équitable :

50% des émissions pour les validateurs,

50% des émissions pour les miners.

Toute contribution doit respecter ce modèle et ne pas introduire :

de déséquilibre entre les rôles,

de mécanismes favorisant un camp,

de dérives économiques ou stratégiques.

Les implications :

les modules Miner et Validator doivent rester équilibrés,

les mises à jour doivent préserver la symétrie,

le subnet doit rester gratuit pour les utilisateurs,

la documentation doit expliciter clairement ce modèle.

# 08 — Gouvernance et transmission du projet
Le Subnet CATAR repose sur la propriété par conviction du réseau Bittensor.

Locking volontaire
Chaque contributeur peut choisir de locker du TAO pour :

renforcer sa conviction,

stabiliser la propriété du subnet,

augmenter sa part des émissions.

Aucune obligation morale ou technique.

Propriété par conviction
Le système garantit :

une maturation sur ~30 jours,

un seuil de challenge à 10%,

une protection contre les prises de contrôle externes,

une gouvernance stable et durable.

Transmission du projet
Le Subnet CATAR doit rester transmissible :

à un autre développeur,

à une équipe,

à une DAO,

à une fondation.

La transmission repose sur :

une documentation claire,

une architecture modulaire,

un code minimal viable,

une roadmap cohérente,

une gouvernance stable.

# 09 — Processus de validation
Chaque contribution est évaluée selon :

cohérence conceptuelle,

qualité technique,

compatibilité avec la roadmap,

respect de l’économie interne,

respect de la gouvernance,

clarté de la documentation.

Les contributions peuvent être discutées via :

Issues GitHub,

Pull Requests,

Discussions techniques.

# 10 — Code de conduite
Les contributeurs doivent :

respecter les autres,

rester constructifs,

éviter les conflits inutiles,

proposer des solutions,

respecter la logique du projet,

documenter leurs modifications.

# 11 — Contact
Pour toute question :
